# СХЕМА Business Platform — v1.4 Kernel

## Purpose

This document is the canonical 12-element kernel workstream for v1.4.

It is intentionally more granular than the ten-stage architecture sequence in `ARCHITECTURE.md`:
- Commercial Action, Order and Economics are tracked as three distinct kernel elements.
- The canonical API / Experience Boundary is tracked as element 12.
- Web/PWA/Android UI implementation remains downstream of the kernel contract.

## Approved 12-element sequence

1. **Foundation / Architecture Contract**
2. **Identity**
3. **Canonical Search**
4. **Discovery + Qualification**
5. **Transactional Persistence**
6. **Intelligence / Research**
7. **AI Gateway**
8. **MAX / Communication Adapter**
9. **Commercial Action**
10. **Order**
11. **Economics**
12. **Canonical API / Experience Boundary**

## System principles

- Modular monolith first; extract services only for measured constraints.
- PostgreSQL is the transactional authority.
- Domain truth is isolated from providers, UI and legacy systems.
- External source observations are never canonical identity.
- Uncertainty is quarantined or sent to review; it is never silently promoted.
- Critical mutations are authorization-, policy- and idempotency-gated.
- Evidence is required for externally-derived critical claims.
- External effects stay outside the core database transaction.
- State change and outbox publication are atomic.
- Retries are at-least-once and handlers are idempotent.
- Audit is append-only and traceable.
- AI is subordinate to authorization, policy, evidence and budget controls.
- MAX is an adapter, not a domain dependency.
- Web, PWA and Android share one canonical API/domain semantics.
- Airtable, Replit and Bitrix24 are not v1.4 system-of-record dependencies.
- One-operator simplicity is preserved; team mode is enabled later by clean contracts.

## Definition of done for the kernel

An element is complete only when:
1. its contract is explicit;
2. domain/application boundaries are respected;
3. critical failure modes fail closed;
4. durable state has an explicit persistence boundary where required;
5. tests cover the critical invariants;
6. CI passes lint, compile, unit tests and integration tests applicable to the element.

## Explicitly outside the v1.4 kernel

- Real production IAM provider wiring.
- Real MAX transport/webhook deployment.
- Concrete external intelligence provider credentials/adapters.
- Web/PWA/Android UI implementation.
- Team collaboration UX.
- Production settlement/payment integrations.
- Airtable/Bitrix24/Replit as system-of-record implementations.

These are downstream integration/product layers and must not be used to redefine kernel semantics.
