# СХЕМА Business Platform — v1.5 Runtime

## Purpose

v1.5 is the runtime/productization boundary built on the frozen v1.4 kernel contracts. It does not replace domain semantics or move business truth into UI, adapters, or legacy systems.

## Stable boundary

- PostgreSQL remains transactional authority.
- Order lifecycle is explicit and persisted under row-lock serialization:
  - draft -> confirmed | cancelled
  - confirmed -> in_progress | cancelled
  - in_progress -> completed | cancelled | failed
  - completed, cancelled, failed are terminal.
- Critical mutations remain authorization-, policy- and idempotency-gated.
- External effects remain outside the core database transaction.
- State change and transactional outbox publication remain atomic.
- Durable jobs, leases, bounded retry and at-least-once execution remain authoritative.
- Authentication is separated from authorization; verified IAM attributes are materialized into explicit permissions.
- Telemetry is non-authoritative and redacted.
- Web, PWA and Android consume the canonical API boundary.
- No external CRM, low-code, migration or mirror system is a transition dependency or system-of-record.

## v1.5+ implementation sequence

1. Freeze and verify v1.4 kernel contracts.
2. Harden production authentication and IAM boundaries.
3. Harden operational observability, recovery, security and supply-chain gates.
4. Add controlled deployment and release checks.
5. Bind concrete MAX and intelligence providers behind existing adapter contracts.
6. Implement and verify the provider-neutral Payment/Settlement contour.
7. Bind the selected production payment provider, webhook verification and settlement reconciliation.
8. Only after the runtime is stable, ship Web/PWA/Android and the Economic Learning Loop.

## Explicit non-goals

- No microservice split without measured operational need.
- No provider-specific logic in the domain.
- No UI-owned business truth.
- No AI authority over business state.
- No external system may become a mirror, migration authority or transactional authority.

## Quality gate

A v1.5 runtime change is accepted only after architecture-contract checks, lint, compile, unit tests and applicable PostgreSQL integration tests are green. Security and recovery gates remain release blockers for production deployment.
